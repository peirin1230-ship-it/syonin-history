# syonin-history — 医療機器 承認番号別 償還区分履歴トラッカー

医療機器の **承認番号（認証番号）ごと** に、特定保険医療材料（**B・C区分**）としての

- いつ保険適用になったか（区分 B1 / B2 / C1 / C2 / R など）
- どの機能区分に掲載されたか、後から **機能区分が変わった／追加された** のはいつか
- 機能区分の **償還価格の改定**・名称変更・廃止
- **レセ電コード（特定器材コード、9桁）** をいつからいつまで使ったか、どのコードへ移ったか（承認番号指定のコードを含む）
- 通知の **一部訂正・差替** で何が直ったか
- どの製品（製品コード / JAN）が、いつ追加されたか

を時系列で追跡するツールです。

## データの出どころ

| 用途 | 出典 | 形式 |
|---|---|---|
| 承認番号 × 製品 × 決定機能区分 × 償還価格 | 厚生労働省「医療機器の保険適用について」（毎月の保医発通知）と、その一部訂正・別紙差替。東海北陸厚生局の掲載ページ（平成20年度〜）から取得 | PDF |
| 機能区分ごとの償還価格・名称・廃止の履歴 | 特定器材マスター（支払基金 → 医療情報基盤・診療報酬審査支払機構）の全件・改定分ファイル（平成24年〜の全版） | CSV |
| 現在の JAN 単位の償還情報（任意） | MEDIS 医療機器データベースのダウンロードファイル（要ダウンロードID） | LZH / CSV |

通知の「決定機能区分」（例: `064 脊椎固定用材料 (5)脊椎ｽｸﾘｭｰ(可動型)`）は、区分番号と名称の類似度、
掲載時の価格の一致で特定器材コード（レセ電コード）に自動で対応付けています。

### レセ電コードの履歴

- 承認番号ごとに、使ったレセ電コードと期間を出します。開始はそのコードの機能区分で初めて掲載された適用日、終了は製品が別の機能区分に移った適用日、またはコードの廃止日（経過措置の終わり）です。
- C1・C2 の新機能区分で次の改定まで使われる「指定承認番号○○」付きのコードは、名称の承認番号から持ち主を判定し、その承認番号の掲載に優先して当てます（他社の指定コードには当てません）。
- 廃止されたコードには、廃止の翌日に有効な同じ名称のコードを「後継候補」として示します。告示での読み替え表は使っていないため、区分が分割・統合されたときの移行先は、製品が再掲載されない限り分かりません。
- ビューアの「レセ電コードで探す」で、コードごとの価格・名称・廃止の履歴と、そのコードを使った承認番号を見られます。

### 対象範囲と限界

- **平成28年度後半〜現在の通知（テキストPDF）** は表をそのまま解析しています。
- **平成20〜28年度前半の通知はスキャン画像** のため、OCR（tesseract）で読み取っています。
  - 承認番号・製品コードは数字・英字専用のモデルで読み、テキスト期の通知と MEDIS にある既知の番号と照合して補正します（1〜2文字の誤読、JAN からの逆引き、チェックデジット）。照合できずチェックデジットも合わない製品コードは捨てています。
  - 機能区分は、区分番号（3桁）と価格から当時の特定器材マスターのコードに当て、表示名はマスターの名称にしています（OCR の日本語は崩れやすいため）。
  - ビューアでは OCR 由来の掲載に「OCR」の印が付きます。古い様式の訂正通知（「項目／誤／正」を文章で書く形式）は反映していません。
- A1（包括）・A2（特定包括）・A3 は含みません（B・C・R区分のみ）。
- 機能区分の変更は「同じ製品コードが、後の通知で同じ区分番号の別の機能区分に掲載された」ことで検出します。改定時の機能区分見直し（例: 令和6年6月の脊椎スクリュー（可動型）の細分化）はこれで拾えますが、製品が再掲載されずに区分だけが読み替えられたケースは、特定器材マスター側の名称変更・廃止としてのみ現れます。
- 自動解析のため、最終確認は出典の通知PDF（ビューアからリンク）で行ってください。

## 使い方

Python 3.10 以上。

```bash
pip install -r requirements.txt
python -m mdtrack update          # 取得 → 解析 → DB構築 → 出力（毎月これだけ）
python -m mdtrack show 30400BZX00034000   # ターミナルで履歴を表示
```

初回は通知PDF約400本（約370MB）の取得と解析に30分ほどかかります。2回目以降は新しい通知だけを処理します。

出力:

| ファイル | 内容 |
|---|---|
| `output/viewer.html` | 検索・時系列表示のビューア（ブラウザで開くだけ）。MEDIS を取り込んでいれば突き合わせ結果も表示。**ローカル用** |
| `docs/index.html` | 同じビューアの公的情報のみ版（共有・GitHub Pages 用） |
| `output/syonin_history.xlsx` | 通知ごとの変更点／承認番号一覧／変更イベント／掲載明細／レセ電コードの履歴／レセ電コードのマスター履歴／通知一覧 |
| `data/syonin.sqlite` | すべてのデータ（SQLite） |

### OCR（スキャン画像の通知）

OCR 結果は `data/parsed/` に入っているので、通常は再実行不要です。やり直す場合:

```bash
# tesseract 5 と日本語・英語の学習データ（tessdata_best の jpn / eng、tessdata_fast の jpn を jpn_fast として）を用意
mkdir -p tessdata
curl -L -o tessdata/jpn.traineddata https://raw.githubusercontent.com/tesseract-ocr/tessdata_best/main/jpn.traineddata
curl -L -o tessdata/eng.traineddata https://raw.githubusercontent.com/tesseract-ocr/tessdata_best/main/eng.traineddata
curl -L -o tessdata/jpn_fast.traineddata https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/jpn.traineddata
pip install opencv-python-headless pypdfium2 numpy
python -m mdtrack ocr --force     # 約4,600頁、2並列で3時間前後
python -m mdtrack ocr-fix         # 補正だけやり直す（MEDIS を取り込んでいると精度が上がる）
```

### MEDIS の取り込み（任意）

```bash
python -m mdtrack medis 20261001_SB_DlAll.lzh
```

毎月ダウンロードして取り込むと、前回との差分（償還区分の追加・削除・価格変化）を承認番号ごとに表示します。
通知の掲載にない特定器材コードが MEDIS にある場合は「要確認」として示します（改定時の区分移行の取りこぼし検出）。
MEDIS のデータは `data/medis/` に置かれ、**Git には含めません**（利用規約上の再配布制限のため）。

## 毎月の更新

- 通知は毎月末に出て翌月1日から適用されます。
- **毎月1日 9:00（日本時間）に Claude のスケジュールタスクが自動で更新します**: このリポジトリを取得して `python -m mdtrack update` を実行し、`data/manifest.json`・`data/parsed/`・`docs/` をコミットして push、共有ビューアも更新します。
- 手元で更新するときは `python -m mdtrack update` を実行してください。`.github/workflows/monthly-update.yml` は同じ処理の手動実行用（予備）です。

## リポジトリ構成

```
mdtrack/            本体（Python パッケージ）
  fetch.py          厚生局ページから通知PDFを収集
  parse_notice.py   通知PDFの表を解析（結合セル・別表・訂正の（誤）（正）に対応）
  ssk.py            特定器材マスターの収集・解析
  catmap.py         決定機能区分 → 特定器材コードの対応付け
  db.py             訂正の反映、イベント生成、SQLite 構築
  medis.py          MEDIS ダウンロードファイルの取込
  ocr_notice.py     スキャン画像の通知の OCR（罫線検出・向き補正・セル単位の読取）
  ocr_repair.py     OCR 結果の承認番号・製品コードの補正
  tess.py           libtesseract を直接呼ぶラッパー
  export.py         Excel・HTMLビューアの出力
data/manifest.json  通知の一覧（取得元URL・通知日・適用日）
data/parsed/        通知ごとの解析結果キャッシュ（gzip JSON）
docs/index.html     共有用ビューア
tests/              単体テスト（python -m pytest）
```
